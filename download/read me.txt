
   C O R R E C T O R
   =================

      Corrector is a computer program that uses Artificial Intelligence (AI from now on)
   to display and correct worksheets in different formats, both on a local computer and
   over an intranet or the Internet.

      It is designed to help teachers with their daily marking tasks while enabling the
   integration of computers into everyday classroom activities.

      The program can be used as a classroom tool in several ways:

     * It can produce reference reports on the exercises students complete throughout the
       school day, including how accurately and successfully they complete them. To do this,
       the program saves detailed reports of all student activity, the entries they make,
       the time spent on their work, the worksheets completed, the answers entered in the
       exercises, and the corrections provided by the AI.

     * It automates the correction process through AI integration. The teacher can configure
       the process and decide which correction criteria should be applied when each worksheet
       is completed.

     * It makes it easier for students to browse the Internet by guiding them along a path
       previously defined by the teacher when creating the initial worksheet. In this way,
       it can provide guided access to online content.

     * Almost any previously available material can be turned into a worksheet, whether it
       was created with another familiar computer program (word processor, drawing program,
       etc.) or even entirely by hand, so that it can be corrected automatically. For example,
       existing paper worksheets only need to be scanned to generate a PDF file. The program
       currently opens HTML, PDF, GIF, JPG, and PNG formats. Students can open and read any
       file in one of these formats, and the teacher only needs to create the corresponding
       correction criteria so that the worksheet can be corrected by the AI.

      The program consists of two independent modules (Acr-ACorrector and Pcr-PCorrector)
   that work together. It is primarily designed so that one module runs on the student's
   computer (Acr) and the other on the teacher's computer (Pcr), although both modules can
   share the same computer and even the same folder without any problems.

      With ACorrector, students can open the worksheet specified by their teacher and stored
   on the computer in one of the formats listed above. The process is as follows:

     - The first time the program starts, it asks for an email address. This feature is not
       yet implemented in the application, but the address must follow the traditional
       name@xxxxx.com format. Next, the user must select the default language from the list
       of available languages (Español, Català, Valencià, Galego, Euskara, Français, and English).

     - The program then asks for the student's name. This is very important when answering
       the worksheet because reports containing the student's answers will use the name entered.
       Names accepted by the operating system must therefore be used, avoiding special characters
       that the program will not accept.

     - After an initial greeting, a dialog box opens and asks the student to select a worksheet
       in one of the supported formats.

     - After the worksheet is selected, the program opens it in the system's default browser.
       The program itself then opens as a small text editor where the user can write the answer
       requested in the worksheet and, when finished, use the Save menu option.

     - When the answer is saved, the program generates a “StudentName.lgx” file in the same
       folder as the worksheet that was previously opened. This file is encrypted and cannot
       be modified by the student, although more answers can be added as long as the same name
       is used. This file must be sent to the teacher, who will use the PCorrector module to
       read it.

      With PCorrector, the teacher can decrypt and read the answers in the *.lgx report file
   generated by the student. The following process must be followed:

   - When the program is opened for the first time, as with Acr, a valid email address must be
     provided and one of the available languages selected.

   - The teacher must then enter their name. After a greeting, the program starts directly and
     displays the following menu in version 0.0.2:

   Let us look at each option:

     - OPEN: This option allows the teacher to open the *.lgx report sent by the student.
       However, the following conditions must be met for the questions to be corrected by
       the AI rather than simply displaying the answers:

        1. Valid “Correction Criteria” for the questions in the student's report must be open.
           The program will notify the user if this is not the case. These criteria can be
           opened or created from the “Criteria” menu, as explained below.

        2. An active Internet connection is required. Otherwise, AI correction will not be
           available or, if the connection is very slow, the minimum response times may be
           exceeded. The program will display a notification in either case.

        3. A valid API key is required. It must be stored in the “pai.dt” file inside the user's
           PCorrector configuration folder:
              “~/Library/Application Support/PCorrector” on macOS.
              “%APPDATA%\PCorrector” on Windows.
              “$XDG_CONFIG_HOME/PCorrector” or “~/.config/PCorrector” on Linux.
           The “Criteria > Configuration > Copy API” menu option lets the user select the “pai.dt” file,
           check whether it works, and copy it automatically into these folders. This is a simple unformatted plain-text
           file containing the encoded API supplied by the company after payment. If this file
           is available and the API has not expired, the program asks the AI to correct the
           written answers using the criteria created by the teacher. After a few seconds, the
           program displays the answers, their corrections, and accompanying comments. In
           version 0.0.2, the program uses OpenAI's API services, specifically the “5.6-Luna”
           version, because it is currently reliable, fast, and economical for the intended
           task. The API can be purchased and paid for on the OpenAI website:
           https://platform.openai.com/home. Based on the tests carried out so far, its cost is
           very low. €1 is enough to correct approximately 2,000 questions of about 200 words
           each. This already low cost is expected to fall even further in the future.

      - ANSWER ONLY: This menu option opens a student's report simply to view what the student
        has written, without involving the AI or requiring an Internet connection. It is highly
        recommended when receiving a new report and reviewing it for the first time to decide
        whether it is worth sending to the AI. This avoids sending nonsensical answers that would
        only use up API credit.

      - LANGUAGE: Changes the PCorrector language. The program must be restarted for the change
        to take effect.

      - EXIT: Closes PCorrector.

      - CRITERIA – Open: Loads a previously created set of “Correction Criteria” into the program.
        A dialog box is displayed where a “*.cri” file must be selected. Its criteria are shown
        on screen once the file has been selected.

      - CRITERIA – New: When using the program for the first time, the teacher must use this option
        to create a new correction criteria file. After selecting it, the teacher is asked to name
        the new criteria file. The only restriction is compatibility with the computer's file-naming
        rules. A name such as “Year 9 Social Studies” would be perfectly valid. When the file is saved,
        the program adds the “.cri” extension and places it by default in the same folder from which
        the application was launched. The teacher can later rename, move, or copy it to another folder,
        but the “.cri” extension must always be retained. A password can also be created using the
        corresponding menu option.

     - CRITERIA – Worksheets – Add: Once the criteria file has been created with the previous option,
       the teacher can add correction criteria for the different questions to be given to students.
       A dialog box opens and asks the teacher to select the file containing the question that the
       student will see. Remember the supported extensions: HTML, PDF, GIF, JPG, and PNG. After the file
       is selected, it opens in the default browser, just as it will when the student opens it. A text
       window then appears with the name of the opened file as its title. The program uses this as the
       worksheet name. The teacher must enter the question and the criteria that the AI will use for
       correction in the text box. For example: “Briefly explain Darwin's theory of evolution (use at
       least 100 words).”

      - CRITERIA – Worksheets – Modify: This option can be used to modify any previously created
        criteria. It provides a way to increase or reduce the AI's correction requirements. In the
        previous example, simply increasing the minimum number of words will require a more rigorous
        answer from the student.

      - CRITERIA – Worksheets – Delete: Completely removes the criteria for a previously stored
        worksheet. Reports containing answers for that worksheet can no longer be corrected by the AI.

      - CRITERIA - Configuration - Copy API: This option installs a copy of the “pai.dt” file containing
        the encoded OpenAI API on the computer. It is an unformatted plain-text file and, because of its
        characteristics, it can be shared by several users or even distributed among all the teaching staff
        at a school. An advanced user can handle its acquisition and download, as well as its expiration.
        Setting an expiration period for the key is highly recommended to prevent uncontrolled distribution.
        A duration of between one and three months may be reasonable.

      - CRITERIA - Configuration - Password - Create: When a new correction criteria file is created using
        Criteria > New, it is created without a password. A password can be added here. Passwords must be
        handled carefully because, if the password is forgotten, there will be no way to open the encrypted file.

      - CRITERIA - Configuration - Password - Modify: This option changes the file password.

      - CRITERIA - Configuration - Password - Delete: This option removes the password so that the file
        no longer has one.

      - ABOUT: Displays the program version.
